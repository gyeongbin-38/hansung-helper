## 1. 서비스의 중심

### 한 줄 정의

학생의 학적·이수 현황·수업 선호를 바탕으로, 지금 필요한 활동과 다음 학기의 선택을 연결하는 개인화 학사관리 서비스.

### 핵심 사용자 질문

“나는 지금 어디까지 왔고, 이번 주에 무엇을 해야 하며, 다음 학기에는 무엇을 선택해야 하는가?”

### 제품 경험

정보 발견 → 나에게 필요한 이유 확인 → 활동 저장·학기 계획·시간표에 반영 → 진행 현황 확인.

홈은 공지 모음도, 숫자만 있는 관리자 대시보드도 아니다. 비교과·대외활동을 발견하는 입구이면서 졸업까지의 다음 행동을 안내하는 개인 작업 공간으로 설계한다. 신청·수강신청·과제 제출의 최종 실행은 초기 범위에서 학교의 공식 시스템으로 연결한다.

## 2. 먼저 구분할 제품 정책

| 항목 | 이번 기획의 기준 |
|---|---|
| 회원가입과 로그인 | 가입은 계정당 한 번. 로그인 세션이 유효하면 홈으로 이동하고 만료되면 로그인한다. 쿠키 삭제만으로 계정을 새로 만들지 않는다. |
| 학번과 학교 인증 | 학번 입력은 계정 식별 정보이며 재학생 인증 완료를 의미하지 않는다. 확인 가능한 인증 경로가 마련되기 전에는 `학교 인증 미완료`로 표시한다. |
| 비밀번호 | 독립 서비스 계정에는 서비스 전용 비밀번호를 사용한다. 학교 포털 비밀번호를 우리 가입 폼에서 수집하는 방식으로 만들지 않는다. 학교 SSO는 연동 승인이 확인된 후 별도 도입한다. |
| 쿠키 선택과 개인정보 처리 | 쿠키 배너, 서비스 약관, 개인정보 수집·이용 안내/동의, 학교 데이터 연결 권한, 알림 권한을 한 개의 동의로 묶지 않는다. |
| 실시간 데이터 | 마지막 수집 시각이 있는 스냅샷과 실시간 상태를 구분한다. 연동하지 않은 기능에 `연동 완료`를 표시하지 않는다. |
| 학사 사실과 개인 계획 | 수강 예정·시간표 저장·활동 완료 체크는 학교의 이수 인정이나 비교과 포인트 지급과 다르다. |
| 졸업 판정 | 서비스의 계산 결과는 참고 지표이며 학교의 공식 졸업 사정을 대신하지 않는다. |

개인정보 처리의 동의를 근거로 삼는 경우에는 목적·항목·보유기간·거부 관련 내용을 고지하고, 필요한 동의 사항을 구분해야 한다. 실제 처리 근거와 최종 약관은 출시 전 검토한다. 쿠키 배너만으로 이 절차가 대체된다고 설계하지 않는다. [R5]

## 3. 전체 정보구조

### 공통 화면 틀

데스크톱: 왼쪽 사이드바 + 상단 유틸리티 바 + 본문.  
상단 바: 서비스 표시 / 전체 검색 / 알림 종 / 사용자 아바타. 브레드크럼은 본문 제목 위 한 곳에 둔다.  
사이드바 하단: 축약 프로필 카드 / 내 정보 / 설정.  
인증 화면: 사이드바 없이 간결한 별도 레이아웃.

## 4. 최초 방문과 재방문

### 신규 사용자 흐름

최초 방문의 서비스 소개·가입/로그인 선택 → 회원가입 → 기본 학적 정보 등록 → 홈 진입 → 수업 성향 설문 제안 → 개인화 홈.

비교과 포인트, 이수 내역, 설문, 학교 데이터 연결은 한 번에 강요하지 않는다. 미입력 항목이 있으면 홈의 필요한 영역에서 정보 보완을 안내한다.

### 재방문 분기

| 상태 | 도착 화면 |
|---|---|
| 계정 없음 | 회원가입 또는 로그인 선택 화면 |
| 계정 있음, 세션 유효, 기본 정보 있음 | 홈 |
| 계정 있음, 세션 유효, 기본 정보 미완료 | 저장된 초기 등록 단계 |
| 계정 있음, 세션 만료 | 로그인 후 기존 상태로 복귀 |
| 설문을 건너뜀 | 홈 진입. 모달 재강제 없이 작은 안내 카드만 표시 |

기본 정보 등록 완료와 설문 완료는 서로 다른 상태로 관리한다. 로그인 유지 상태와 쿠키 동의 선택도 별개로 관리한다. 공용 PC에서는 로그인 유지를 선택하지 않을 수 있게 한다.

### 쿠키 배너

위치: 첫 방문 시 하단의 비모달 배너.  
동작: `선택 쿠키 거부 / 선택 관리 / 모두 허용`을 제공한다. 필수 세션 처리에 대한 설명과 선택 분석 쿠키를 구분한다. 선택 분석 쿠키는 기본 꺼짐으로 제안한다. 거부해도 기본 학사관리 기능은 이용 가능하게 한다. 설정에서 선택 변경·철회 경로를 제공한다.

선택 분석 도구를 실제 사용하지 않는다면 사용한다고 꾸미지 않는다. 그 경우 배너는 실제 저장 항목에 관한 간단한 안내로 축소한다. 개인정보 처리방침에 대한 단순 확인을 모든 처리의 포괄 동의로 취급하지 않는다.

### 기본 정보 등록

| 정보 | 입력 방식 | 비고 |
|---|---|---|
| 표시 이름 | 짧은 텍스트 | 실명 대신 별칭 허용 제안 |
| 입학연도·학적 구분 | 선택 | 학번에서 자동 추정한 값은 확인을 받는다. |
| 소속 학과·학부 | 검색 가능한 드롭다운 | 공식 목록 확인 전 완전한 목록이라고 주장하지 않는다. |
| 적용 트랙 | 학과에 연동된 선택 | 제1·제2트랙, 미선택·해당 없음 지원. 모든 학과가 같은 구조라고 가정하지 않는다. |
| 현재 학기·이수학기 | 선택 | 학년과 혼동하지 않는다. |
| 목표 졸업학기 | 선택 | 선택 입력, 추후 수정 가능 |
| 이수 내역·비교과 포인트 | 수동 입력 또는 연결/가져오기 | 모르는 값은 `모름/나중에 입력`. 0으로 채우지 않는다. |

기본 등록에 연락처·생년월일·프로필 사진을 요구하지 않는다. 졸업 규정 적용에 필요한 편입·복수전공 등의 정보는 해당 사용자에게만 추가로 묻는다.

### 라이트박스형 수업 성향 설문

홈의 `맞춤 추천 설정하기`를 누르면 배경을 어둡게 하고 중앙에 단계형 설문을 연다. 첫 홈 진입에서는 안내 카드로 제안하고, 사용자가 시작을 선택한 뒤 설문을 연다. 건너뛰기를 제공하고 재방문 시 재강제하지 않는다. 모바일에서는 전체 화면 시트로 전환한다.

제안: 총 6문항, 문항당 한 화면 또는 연관된 두 문항씩 3단계.

| 문항 | 선택 예시 | 활용 |
|---|---|---|
| 이번 학기 우선 목표 | 졸업요건 충족 / 전공 심화 / 진로 탐색 / 일정 여유 | 추천의 목적 |
| 선호 수업 시간 | 오전 / 오후 / 상관없음 | 시간표의 선호 조건 |
| 수업 불가능 시간 | 요일·시간 블록 / 없음 | 시간표의 필수 제약 |
| 수업 방식 선호 | 이론 / 실습 / 프로젝트 / 상관없음 | 과목 추천 정렬 |
| 평가 방식 선호 | 시험 / 개인 과제 / 팀 프로젝트 / 상관없음 | 확인된 평가 정보가 있는 과목에만 반영 |
| 학기 구성 선호 | 공강일 확보 / 고른 배치 / 희망 학점 범위 | 시간표와 학기 계획 후보 비교 |

관심 진로·키워드는 결과 화면에서 선택 태그로 보완한다. 필수 시간 충돌 회피와 취향 점수는 분리한다. 성향 점수를 임의의 심리 진단이나 성격 유형으로 변환하지 않는다.

설문에는 `이전 / 다음 / 건너뛰기 / 완료 / 닫기`와 단계 표시가 있다. 닫으면 입력한 초안을 보존하고, 최종 완료 전에는 기존 선호를 덮어쓰지 않는다. 중첩 모달을 만들지 않는다. 모달 내부로 키보드 초점을 이동하고, Tab 이동을 내부로 제한하며, Escape로 닫고 호출 지점으로 초점을 되돌린다. [R7]

쿠키 배너·설문·브라우저 알림 권한 요청을 동시에 띄우지 않는다.

## 5. 홈의 최종 구성

### 전체 배치

1. 페이지 제목과 한 줄 개인 요약.
2. 해당될 때만 표시하는 중요 고정 안내.
3. 비교과·대외활동 Hero 캐러셀.
4. `지금 할 일` 최대 3개.
5. 졸업 준비 현황과 학사 KPI.
6. 이번 주 일정·코스모스 학습 알림.
7. 맞춤 과목·활동 추천과 학기 계획 연결.

큰 화면에서는 Hero 8열 + 프로필·다가오는 일정 4열의 상단 배치를 제안한다. 아래 개인 현황은 본문 전체 너비를 사용한다. 모바일에서는 중요한 안내와 Hero를 먼저, 축약 프로필을 그 다음에 놓고 단일 열로 정리한다.

### 5.1 상단 요약

예시 문구: “이번 주에 확인할 일정과 나에게 맞는 활동을 모았어요.”

근거가 있을 때만 `마감 임박 활동 2개`, `정보 확인 필요 1개`처럼 숫자를 표시한다. 데이터가 없으면 꾸며낸 개인화 요약을 만들지 않는다.

### 5.2 중요 고정 안내

수강신청 일정 변경, 졸업 판단에 영향을 주는 데이터 불일치, 연동 재인증 필요 등에 사용한다. 반드시 해야 할 행동은 캐러셀의 뒤쪽 슬라이드에만 넣지 않는다.

한 번에 가장 중요한 안내를 먼저 보여주고 같은 원인의 오류를 중복 노출하지 않는다. 중요한 일정은 알림함과 학사일정에서도 다시 찾을 수 있게 한다.

### 5.3 Hero 캐러셀

목적: 많은 공지를 모두 순환시키는 것이 아니라, 관심을 가질 만한 정보 3~5개를 선별해 요약한다.

각 슬라이드의 정보 구조:

| 영역 | 내용 |
|---|---|
| 구분 | 교내 비교과 / 대외활동 / 학교 소식 |
| 제목 | 1~2줄의 원문 의미를 유지한 제목 |
| 요약 | 무엇을 하고 누구에게 유용한지 2줄 |
| 핵심 조건 | 모집 대상, 모집 마감, 운영 일시, 장소·방식 |
| 혜택 | 원문에서 확인된 비교과 포인트·혜택 |
| 추천 이유 | 관련 선호·부족 요건 등 확인 가능한 개인화 이유 |
| 상태 | 모집 중 / 마감 / 일정 확인 필요 |
| 행동 | `자세히 보기`가 주 버튼, `저장`이 보조 버튼 |
| 근거 | 출처와 마지막 확인 시각 |

공고 마감과 실제 운영 일시를 별도 필드로 표시한다. 외부 활동에는 비교과 인정 여부를 별도 표시하며, 확인되지 않으면 `인정 여부 확인 필요`로 둔다. 활동이 종료됐다는 사실과 포인트가 승인됐다는 사실을 구분한다.

기본 동작은 수동 넘김을 권장한다. 이전·다음, 현재 위치, 터치 스와이프를 제공한다. 자동 넘김을 추가하면 일시정지·재생 버튼을 제공하고, 마우스 호버와 키보드 초점 진입 시 중지한다. 키보드 초점 때문에 중지된 자동 넘김은 사용자의 재생 조작 없이 재개하지 않는다. [R6]

후보가 1개면 단일 카드로, 0개면 정적 안내와 전체 활동 보기로 바꾼다. 가짜 활동으로 빈 자리를 채우지 않는다. 이미지 안에 있는 글자만으로 중요한 조건을 전달하지 않는다.

### 5.4 지금 할 일

최대 3개의 실행 가능한 항목을 제공한다. 각 항목은 `해야 할 일 / 필요한 이유 / 기한 / 다음 행동`을 가진다.

예시: “선택필수 영역을 확인하세요 → 아직 분류되지 않은 이수 과목이 있어요 → 이수 내역 검토”.

할 일의 완료 처리는 개인 작업 상태만 변경한다. 학점·포인트·졸업요건을 자동 충족 처리하지 않는다.

### 5.5 개인 현황

`졸업요건 체크리스트 충족률 / 총 이수학점 / 졸업 인정 비교과 포인트 / 이번 학기 계획`을 구분해 보여준다. 모든 카드에는 단위, 기준, 상세 보기, 데이터 상태가 있다.

### 5.6 일정·학습 정보

다가오는 학교 일정, 저장한 활동 일정, 개인 일정, 확인 가능한 LMS 학습 일정을 출처 배지로 구분한다. LMS 미연결 사용자는 일반 학교 일정과 개인 일정은 계속 사용할 수 있다.

코스모스 연결 전에는 가짜 개인 과제나 출석 현황 대신 `학습 일정 연결하기` 또는 `직접 일정 추가`를 보여준다. 강의자료 다운로드나 과제 제출 기능을 홈에 새로 구축하지 않는다.

## 6. 상세 화면과 브레드크럼

브레드크럼은 방문 기록이 아니라 서비스 내 고정된 위치를 나타낸다. 제목 위에 두고 현재 페이지는 링크로 만들지 않는다.

예시:

- 홈 > 비교과·대외활동 > 활동명
- 홈 > 졸업요건 > 선택필수교양
- 홈 > 과목 추천 > 과목명
- 홈 > 학사일정 > 일정명
- 홈 > 설정 > 데이터 연결

상위 목록으로 돌아갈 때 검색어·필터·정렬을 보존한다. 알림함에서 진입한 경우 `알림함으로 돌아가기`는 별도 동작으로 제공하고 브레드크럼을 방문 경로로 바꾸지 않는다. 좁은 화면에서는 중간 계층을 접되 상위 목록 접근은 유지한다.

### 활동 상세

제목·상태·저장 → 핵심 조건 → 쉬운 요약 → 추천 이유 → 상세 내용·주의사항 → 비교과 인정 조건 → 출처·확인 시각 → 공식 신청 페이지 열기.

`공식 신청 페이지 열기`는 외부 이동임을 표시한다. 링크를 클릭한 것만으로 `신청 완료`나 `참여 완료`로 바꾸지 않는다.

### 졸업요건 상세

적용 대상·규정 버전 → 충족 기준 → 현재 인정 내역 → 부족한 부분·확인 필요 → 해당 요건에 연결되는 과목·활동 → 학기 계획에 추가 → 학교 원문.

### 과목 상세

과목명·코드 → 학점·영역 → 개설 학기·분반 확인 상태 → 시간·선수과목·평가 방식 중 확인된 항목 → 추천 이유 → 시간표 초안 추가 / 학기 계획에 담기.

과목 소개에 존재한다는 이유만으로 다음 학기 개설을 확정하지 않는다. LMS의 현재 수강 목록을 대학 전체 개설과목 목록으로 취급하지 않는다.

## 7. 프로필 카드와 개인 통계

### 프로필 카드

내 정보 상단에는 표시 이름, 이니셜·선택 사진, 소속, 트랙, 현재 학기, 목표 졸업학기, 학교 인증 상태를 표시한다. 학번은 기본 마스킹하고 명시적인 상세 보기에서만 본인에게 전체를 보여준다.

홈 또는 사이드바 하단에는 이름·소속·아바타만 표시하는 축약형을 사용한다. 긴 학적 정보와 통계는 내 정보 페이지로 보낸다.

사용자 입력값, 공식 출처에서 가져온 값, 확인되지 않은 값은 서로 다른 배지로 구분한다. 공식 가져오기 값은 사용자가 임의 수정해서 공식 사실로 덮어쓰는 대신 정정 요청·재확인 흐름을 둔다.

### 통계 구성

| 통계 | 표현 | 데이터 규칙 |
|---|---|---|
| 학기별 취득 학점 | 막대그래프 | 이수 완료 학점과 이번 학기 수강·계획 학점을 분리 |
| 누적 졸업 인정 비교과 포인트 | 선그래프 + 현재 값 | 취득일별 기록이 있을 때만 시계열 생성 |
| 전공·교양 등 영역별 충족 | 수평 막대 / 프로그레스 바 | 학생에게 적용되는 규정에 따라 분류 |
| 학기 계획 대비 진행 | 완료·진행·미시작 수치 | 개인 계획의 진행도이며 공식 이수 결과가 아님을 표시 |

모든 차트에는 기간, 단위, 데이터 출처, 표 형태의 대체 보기, 짧은 해석을 제공한다. 이력 없이 현재 총점만 입력한 사용자의 과거 추세를 만들어내지 않는다. 데이터가 한 시점뿐이면 숫자 카드로 대체한다.

사용자 통계 화면에 학교 평균·학과 순위·상위 몇 퍼센트 같은 비교 수치를 근거 없이 넣지 않는다. 성향은 선택한 선호 태그로 보여주며 임의의 레이더 점수로 과장하지 않는다.

### 프로그레스 바와 졸업 지표

영역별 진행률은 `인정 완료 수량 ÷ 해당 영역의 필요 수량`으로 계산한다. 바의 최대 길이는 100%로 제한하되 초과 취득 수량은 실제 숫자로 보존한다. 기준이나 입력값이 없으면 계산 대기로 두며 0%로 보이지 않는다.

전체 지표를 노출할 때의 이름은 `졸업요건 체크리스트 충족률`이다. 규정의 정규화된 적용 필수 항목 중 충족된 항목 수를 전체 적용 필수 항목 수로 나눈 값이며, 학점과 포인트의 임의 평균을 사용하지 않는다. 항목 분할 방식과 규정 버전을 고정하고 `충족 x / 적용 y`를 함께 보여준다.

적용 규정이 미확정이거나 판단에 필요한 자료가 누락되면 전체 퍼센트 대신 `계산 대기 · 정보 확인 필요`를 표시한다. 세부 상태는 `충족 / 미충족 / 확인 필요 / 해당 없음`으로 구분하고, 해당 없음은 분모에서 제외한다. 수강 중·계획 중인 항목은 별도 보조 표시이며 실제 충족으로 계산하지 않는다.

주의 문구: “입력·연동된 자료에 따른 참고 결과입니다. 최종 졸업 여부는 학교의 공식 사정 결과를 확인하세요.”

## 8. 알림·토스트·배너의 책임 분리

| 유형 | 목적 | 유지·저장 | 사례 |
|---|---|---|---|
| Notification | 나중에도 찾아야 하는 사건과 예정 일정 | 알림함에 남김 | 수강신청 시작 전, 일정 변경, 저장 활동 마감 |
| Toast | 방금 실행한 저장·변경의 결과 | 보통 잠시 표시 | 시간표 초안 저장, 선호 업데이트 |
| Inline banner | 해결 전까지 영향을 주는 상태 | 관련 화면에서 유지 | 연결 만료, 자료 충돌, 판단 기준 미확인 |
| 입력 오류 안내 | 수정할 필드를 알려줌 | 필드 옆에 유지 | 누락된 학기, 유효하지 않은 입력 |

### Notification

상단 종 아이콘에 안 읽은 개수를 표시하고 클릭하면 오른쪽 알림 패널을 연다. 전체 알림은 `/notifications`에서 확인한다. 전체·수강신청·학사일정·활동·학습·시스템으로 분류하며 읽음 처리와 관련 상세 이동을 제공한다.

알림 필드: 제목, 이유, 대상 이벤트, 실제 예정 일시, 알림 생성 시각, 원문, 읽음 상태, 관련 경로, 일정 버전.

수강신청 알림은 개인 대상 학년·학기와 공식 일시가 확인된 경우에만 예약한다. 제안 기본 선택지는 전날·1시간 전·10분 전이다. 날짜만 확인된 일정에는 정확한 시각의 카운트다운을 표시하지 않는다. 일정이 바뀌거나 취소되면 이전 예약을 취소·수정하고 중복 알림을 방지한다. 선착순 잔여석 실시간 감시와 자동 수강신청은 초기 범위에서 제외한다.

사이트 안의 알림함과 운영체제·브라우저 푸시는 분리한다. 사용자가 `수강신청 알림 받기` 등을 누른 시점에 채널을 설명하고 필요한 브라우저 권한을 요청한다. MDN은 사용자 상호작용에 대한 응답으로 권한을 요청하도록 안내하며, 지원 브라우저와 보안 연결 요건을 명시한다. [R8]

권한 거부·미지원이면 사이트 알림함으로 대체한다. 푸시 예약 저장과 실제 전달 성공을 구분한다. 닫힌 브라우저에서의 발송은 별도 푸시 인프라가 검증되기 전까지 지원 완료로 표시하지 않는다.

### Toast

데스크톱 위치 제안: 화면 오른쪽 24px, 위에서 112px. 상단 헤더보다 아래인 우측 중상단에 너비 약 360px의 배너형 메시지로 표시한다. 모바일은 헤더 아래 좌우 16px 여백으로 배치한다.

성공·단순 안내는 기본 5초, 닫기 버튼 제공, 호버·키보드 초점 시 시간 경과 정지. 동시에 최대 3개만 표시하고 유사 메시지는 합친다. 오류와 중요한 실행 취소 기회는 자동 소멸에만 의존하지 않고 관련 화면에 남긴다.

예시 문구:

- “시간표 초안을 저장했어요. 학교 수강신청에는 반영되지 않았어요.”
- “수업 선호가 저장됐어요. 추천을 다시 계산하고 있어요.”
- “학기 계획에 과목을 추가했어요. 아직 이수학점에는 포함되지 않아요.”
- “저장하지 못했어요. 입력한 내용은 유지했어요. 다시 시도해 주세요.”

페이지 이동, 카드 보기, 단순 필터 변경마다 토스트를 띄우지 않는다. 저장 요청이 완료되기 전에 성공 메시지를 내보내지 않는다. 상태 메시지는 초점을 강제로 빼앗지 않고 보조기술이 인지할 수 있게 전달한다. [R9]

서버 저장 실패 시 입력 초안을 유지한다. 데이터 변경으로 추천 재계산이 필요하면 `저장 완료`와 `추천 반영 중`을 구분한다.

## 10. 학교·코스모스·외부 활동 데이터 구상

### 확인한 사실

한성대학교 공식 업무 안내는 한성 e-Class(LMS)의 PC 버전과 모바일 앱 코스모스를 함께 관리·운영하는 것으로 설명한다. 따라서 코스모스 연동은 앱 화면 자체를 긁는다는 전제보다 학교 e-Class/LMS의 허용된 데이터 연결 대상으로 정의한다. [R1]

스마트자기관리시스템 공개 페이지에는 비교과프로그램과 마이페이지의 비교과 포인트 내역 메뉴가 있다. 학교 공지는 개인 졸업 인정 비교과 포인트의 확인 경로를 이 시스템으로 안내한다. [R2][R3]

확인한 2026년 4월 학부 공지는 130학점과 800포인트 및 입학연도 적용 조건을 안내한다. 이는 이전 와이어프레임의 수치를 그대로 규칙으로 쓰면 안 된다는 근거이지, 모든 학생의 기준을 130/800으로 고정하라는 의미가 아니다. [R3]

### 수집 출처를 논리적으로 분리

| 출처 | 목표 데이터 | 현재 확인 수준 | 초기 대안 |
|---|---|---|---|
| 학교 홈페이지·공식 학사 공지 | 일정, 수강신청 안내, 졸업 관련 공지·규정 | 공지별 원문 확인 필요 | 관리자 검토 후 등록 + 원문 연결 |
| 한성 e-Class / 코스모스 | 개인 수강 강좌, 수업 공지, 과제·학습 일정 등 | 공개 진입·로그인 화면 확인. 개인 데이터 자동 접근 미검증 | 직접 일정 입력 + 공식 화면 열기 |
| 스마트자기관리시스템 | 공개 프로그램 정보, 개인 졸업 인정 포인트 | 공개 프로그램·메뉴 확인. 개인 이력 접근 미검증 | 공개 정보 요약 + 본인 수동 입력 |
| 종합정보시스템 | 학적·이수 내역 등 목표 학사 데이터 | 로그인 진입 확인. 세부 조회·가져오기 미검증 [R4] | 지원 형식 확인 후 본인 내역 가져오기·수동 등록 |
| 외부 활동의 공식 주최처 | 모집요강, 대상, 일정, 혜택 | 대상 사이트 미정 | 출처가 분명한 수동 등록부터 시작 |

LMS의 학습 완료를 공식 이수학점으로 대체하지 않는다. 외부 활동 참가만으로 비교과 포인트가 생긴다고 처리하지 않는다. 학교 공지는 교외활동의 증빙 신청과 승인 절차를 안내한다. [R3]

### 제안 수집 구조

공개 정보: 허용 범위 확인 → 주기적 수집 또는 관리자 등록 → 정규화·중복 제거 → 요약·필수 조건 검토 → 공용 DB·캐시 → 사용자 조회.

개인 정보: 사용자의 데이터 범위 선택 → 허용된 연결 또는 본인 가져오기 → 사용자별 비공개 저장 → 규정 기반 계산 → 개인 화면.

홈을 열거나 활동을 검색할 때마다 학교 원본을 다시 긁지 않는다. 수동 새로고침 요청도 중복 실행을 막는 작업으로 처리한다. 실제 주기·요청 제한은 학교 정책과 운영 관찰을 확인한 후 정한다. 공용 캐시에 개인 성적·학번·과제·포인트 이력을 섞지 않는다.

공개 접근 가능 여부, robots 정책, 이용조건, 재사용 권한, 개인 데이터 접근 권한은 별도 확인 항목이다. CAPTCHA·접근 제한을 우회하는 방식을 기본 연동으로 삼지 않는다. 공식 API·SSO가 없다고 확인된 것도 아니므로 존재 여부를 단정하지 않는다.

### 데이터 출처 표시

화면에서 구분할 상태: `공식 출처 / 사용자 입력 / 데모 데이터`, `기준일`, `마지막 확인`, `확인 필요`.

연결 상태: `지원 준비 중 / 미연결 / 연결 중 / 연결됨 / 갱신 필요 / 연결 만료 / 오류 / 일부 성공`.

허가·구현 전의 커넥터는 `지원 준비 중`이다. 이 상태의 버튼은 설명과 대안을 보여주며 클릭만으로 `연결됨`이 되지 않는다. 실제 연결 실패와 미지원 상태도 혼동하지 않는다.

자료가 충돌하면 이전 값과 새 값, 각각의 출처·시각을 보여주고 검토 대상으로 표시한다. 무조건 마지막 값으로 덮어쓰지 않는다. 원문 수정·삭제·일정 변경이 있으면 캐러셀, 상세 페이지, 저장 목록, 관련 알림에도 영향을 반영한다.

시간은 실제 일시와 시간대 정보를 보존하고 화면 기본 표시는 한국 시간으로 한다. 날짜만 있는 공고에 임의의 마감 시각을 만들지 않는다.

## 12. 최종 디자인 가이드

### 12.1 디자인 방향

첨부한 Apple Reference Design System은 **시각적 참고 자료**로 사용한다. 그대로 복제하는 것이 아니라 다음 원칙만 제품에 맞게 가져온다.

1. 콘텐츠가 먼저 보이고 컨트롤은 시각적으로 절제한다.
2. 한 화면에서 주요 행동 색상은 하나의 파란 계열 액센트에 집중한다.
3. 정보 계층은 장식보다 타이포그래피, 여백, 정렬, 크기 차이로 만든다.
4. 카드와 패널은 기본적으로 평면적이고 가볍게 유지한다.
5. 반투명·블러 효과는 내비게이션과 제어층에서만 제한적으로 사용한다.
6. 개인정보·권한·오류·위험 상태는 모호한 미사여구 없이 직접적으로 설명한다.
7. 학사관리 서비스이므로 마케팅 페이지처럼 과도한 대형 타이포그래피나 장식적 Hero를 반복하지 않는다.

### 12.2 반드시 피할 시각 패턴

이 프로젝트에서는 아래 패턴을 **사용하지 않는다.**

#### Side accent bar 금지
카드, 알림, 섹션 제목, 선택 메뉴의 왼쪽 또는 오른쪽에 세로 색상 막대를 붙여 상태를 표현하지 않는다.

사용하지 않는 예:
- 카드 왼쪽 4px 파란색 막대
- 경고 카드 왼쪽 노란색 세로 띠
- 선택된 사이드바 항목의 좌측 세로 액센트 라인
- 섹션 제목 옆 세로 컬러 바

대신 다음 조합을 사용한다.
- 제목 굵기와 크기
- 작은 상태 배지
- 아이콘
- 연한 표면 배경
- 1px 이하의 중립 보더
- 버튼/링크 색상
- 충분한 여백

#### Side-tab card 금지
카드의 옆면에서 탭이 튀어나오거나, 카드 측면에 세로 탭을 붙여 카테고리나 상태를 표현하지 않는다.

사용하지 않는 예:
- 카드 오른쪽으로 돌출된 `추천`, `NEW`, `필수` 탭
- 카드 왼쪽에 세로 글자가 들어간 분류 탭
- 카드 자체를 여러 층의 옆탭처럼 쌓는 구성

대신 다음을 사용한다.
- 카드 상단의 작은 badge/chip
- 콘텐츠 영역 위쪽의 일반 탭
- segmented control
- 필터 chip
- 카드 내부 메타 정보 행

### 12.3 색상 역할

| 역할 | 기준 |
|---|---|
| App Background | `#f5f5f7` |
| Surface | `#ffffff` |
| Primary Text | `#1d1d1f` |
| Secondary Text | `#6e6e73` |
| Tertiary Text | 필요 시 `#515154` |
| Primary Action | `#0071e3` |
| On Primary | `#ffffff` |
| Link / Outline Action | `#0066cc` |
| Dark Surface Link | 어두운 표면을 실제 사용하는 경우에만 `#2997ff` |

상태 색상은 성공·주의·오류의 의미를 위해 별도로 정하되 **색만으로 상태를 구분하지 않는다.** 텍스트·아이콘·배지를 반드시 함께 사용한다.

학교 공식 브랜드 색을 쓰는 경우에도 전체 인터페이스를 학교 색으로 채우지 않는다. 주요 인터랙션 색상과 충돌하지 않는 범위에서 로고·브랜딩 영역에 제한한다.

### 12.4 타이포그래피

첨부 디자인의 Display/Text 역할 분리를 참고하되, 실제 웹에서는 한국어 가독성과 배포 환경을 우선한다.

권장 역할:

| 역할 | 데스크톱 기준 |
|---|---:|
| Page title | 32px / 600~700 |
| Section title | 24px / 600 |
| Card title | 18~20px / 600 |
| Body | 16~17px / 400 |
| Secondary | 14px / 400 |
| Meta / Caption | 12~13px / 400 |

원칙:
- 큰 제목은 짧게 유지한다.
- 한국어 본문에 영문 자간 값을 기계적으로 적용하지 않는다.
- 날짜, 마감, 학점, 포인트처럼 의사결정에 중요한 값은 12px 캡션에만 숨기지 않는다.
- 한 카드 안에서 폰트 크기를 과도하게 많이 사용하지 않는다.

### 12.5 레이아웃

| 항목 | 최종 기준 |
|---|---|
| 데스크톱 사이드바 | 240px |
| 접힌 사이드바 | 72px |
| 상단 유틸리티 바 | 64px |
| 본문 최대 폭 | 사이드바 제외 최대 1440px |
| 데스크톱 본문 패딩 | 32px |
| 모바일 본문 패딩 | 16px |
| 기본 그리드 | 데스크톱 12열 |
| 섹션 간격 | 32px |
| 카드 간격 | 16~24px |
| 카드 내부 패딩 | 기본 24px, 조밀형 16px |
| 카드 반경 | 프로젝트 로컬 값으로 18~20px |
| 모바일 | 단일 열 중심 |

카드를 모든 정보를 감싸는 기본 장식으로 남발하지 않는다. 서로 연관된 텍스트와 수치가 같은 정보 그룹이면 배경 없이도 충분한 여백과 구분선만으로 구성할 수 있다.

### 12.6 카드 디자인

기본 카드:
- 흰색 Surface
- 얇은 중립 보더 또는 보더 없음
- 큰 그림자 없음
- 약한 배경 대비와 여백으로 영역 구분
- 제목 → 핵심 수치/내용 → 보조 정보 → 행동 순서

카드의 중요도를 그림자 크기나 컬러 막대 크기로 표현하지 않는다.

상태가 필요한 경우 카드 상단이나 제목 옆에 다음처럼 표시한다.

`[확인 필요] 졸업요건 데이터`

`[마감 D-2] 교내 비교과 프로그램`

`[사용자 입력] 비교과 320P`

### 12.7 탭과 선택 상태

페이지 내부의 범주 전환은 다음 우선순위를 사용한다.

1. 상단 텍스트 탭
2. segmented control
3. chip/filter
4. 드롭다운

선택 상태는:
- 텍스트 굵기
- 약한 배경 채움
- 하단 underline
- 체크 아이콘

중 하나 또는 둘을 조합해 표현한다.

**세로 side-tab은 사용하지 않는다.**

사이드바의 선택 상태도 좌측 세로 바 대신 다음처럼 처리한다.
- 선택 항목 전체에 약한 배경색
- 아이콘과 텍스트의 foreground 강화
- 둥근 직사각형 또는 pill 형태의 selection surface

### 12.8 버튼

#### Primary
- 배경 `#0071e3`
- 글자 `#ffffff`
- 높이 44px를 기본 큰 행동으로 사용
- pill에 가까운 충분한 radius
- 한 영역에서 가장 중요한 행동 하나에 우선 사용

#### Secondary
- 투명 또는 흰색 배경
- `#0066cc` 텍스트
- 필요 시 1px outline
- Primary와 시각적 우선순위가 충돌하지 않게 함

#### Compact
- 작은 카드·필터·보조 행동에 약 36px 높이 사용 가능

원칙:
- 한 카드에 파란색 Filled 버튼을 여러 개 남발하지 않는다.
- 위험 작업은 일반 Primary와 구분한다.
- 아이콘만 있는 버튼은 tooltip/accessible label을 제공한다.

### 12.9 사이드바

사이드바는 유지한다. 역할은 **내비게이션**이며 카드나 장식 패널처럼 보이게 만들지 않는다.

구성:
- 상단: 서비스 로고/이름
- 중앙: 주요 메뉴
- 하단: 축약 프로필 → 내 정보 → 설정

선택 메뉴는 side accent bar 없이 배경 채움으로 표현한다.

권장 메뉴 순서:
1. 홈
2. 시간표 짜기
3. 비교과·대외활동
4. 학사일정
5. AI 상담
6. 졸업요건
7. 학기별 계획
8. 과목 추천

구분선은 꼭 필요한 위치에만 사용한다.

### 12.10 Hero 캐러셀

Hero는 마케팅 배너가 아니라 **학생에게 필요한 정보 요약 영역**이다.

구조:
- 작은 category badge
- 제목
- 1~2줄 요약
- 마감/운영기간/대상/혜택
- 추천 이유
- `자세히 보기`
- `저장`

시각 원칙:
- 배경 이미지 위에 긴 텍스트를 겹치지 않는다.
- 포스터 이미지를 전체 카드로 사용하지 않는다.
- 정보 영역과 이미지를 분리하거나 이미지가 없어도 완성되는 레이아웃을 사용한다.
- Side accent bar 사용 금지.
- Side-tab 사용 금지.
- 페이지네이션은 dot 또는 `1 / 4` 형태.
- 이전/다음 컨트롤은 캐러셀 내부의 단순 아이콘 버튼.

### 12.11 통계와 프로그레스

개인 통계는 장식 그래프보다 **판단 가능한 숫자**를 우선한다.

각 통계 영역은:
- 현재 값
- 기준
- 변화 또는 기간
- 그래프
- 데이터 출처/상태

순으로 구성한다.

프로그레스 바:
- 수평형
- bar 자체는 단순하게 유지
- `현재 / 기준` 숫자를 항상 함께 표시
- 100% 이상은 실제 숫자는 보존하되 bar는 100%에서 멈춤
- 미확정 데이터는 0%로 표시하지 않고 `계산 대기`로 표시

### 12.12 브레드크럼

상세 페이지 제목 위에 배치한다.

예:
`홈 > 비교과·대외활동 > 활동명`

시각적으로는 작은 보조 텍스트 계층이며 별도 카드나 side-tab으로 만들지 않는다.

### 12.13 Notification / Toast / Inline Banner

#### Notification
지속적으로 확인해야 하는 정보.
- 알림함에 저장
- 수강신청, 일정 변경, 활동 마감, 학습 일정 등에 사용

#### Toast
직전 행동 결과.
- 우측 중상단
- 약 360px
- 성공/안내 기본 5초
- 동시에 최대 3개
- 단순 페이지 이동마다 표시하지 않음

Toast 역시 왼쪽 컬러바를 넣는 side accent 패턴을 사용하지 않는다.
상태는 아이콘 + 제목 + 메시지 + 필요 시 버튼으로 표현한다.

#### Inline Banner
해결 전까지 영향을 주는 상태.
- 연동 만료
- 자료 충돌
- 졸업 판단 정보 부족

Banner도 세로 강조 막대 없이 전체 배경의 미세한 톤 차이, 아이콘, 제목으로 구분한다.

### 12.14 라이트박스/모달

수업 성향 설문에 사용한다.

원칙:
- 중앙 집중
- 배경 dim
- 한 번에 하나의 목적
- 중첩 모달 금지
- 단계 표시 제공
- 닫아도 초안 유지
- 모바일에서는 full-screen sheet 허용
- 키보드 초점이 모달 안에서 순환되고 닫으면 원래 위치로 복귀

### 12.15 반투명·블러

허용:
- 상단 헤더
- 모바일 드로어 배경
- 일부 고정 내비게이션

지양:
- 통계 카드 전체
- 졸업요건 카드
- 리스트 카드
- 데이터 테이블
- 활동 상세 본문
- 프로필 카드 전체

Liquid Glass 같은 표현은 분위기 참고 수준으로만 사용하고 콘텐츠 계층 전체를 유리 재질로 만들지 않는다.

### 12.16 반응형

#### ≥1200px
- 전체 사이드바
- 12열
- 홈 Hero + 보조 패널 8:4 가능

#### 768~1199px
- 접힌 사이드바 또는 compact navigation
- 2열/1열 혼합

#### ≤767px
- 사이드바 대신 drawer
- 주요 콘텐츠 단일 열
- 캐러셀 카드 한 장 중심
- 차트는 가로 스크롤보다 축약형/목록형을 우선
- Toast는 헤더 아래 좌우 16px

정확한 breakpoint는 프로젝트 구현 환경에서 조정 가능하며 디자인 참고 자료의 Apple 공식 토큰으로 취급하지 않는다.

### 12.17 접근성

- 키보드만으로 주요 기능 사용 가능
- hover만으로 정보를 숨기지 않음
- focus 상태 명확
- 색상만으로 상태 표현 금지
- 차트에 텍스트/표 대체 제공
- 모션 감소 설정 지원
- 캐러셀 자동 넘김 사용 시 정지 제어 제공
- 모달 포커스 트랩과 복귀 지원
- 충분한 클릭 영역 확보

### 12.18 화면 톤

최종 분위기:

**밝고 정돈된 개인 학사 워크스페이스.**

- 회백색 배경
- 흰색 정보 표면
- 선명한 검정 계열 타이포그래피
- 필요한 위치에만 파란 Primary Action
- 장식보다 정보 위계
- 과한 gradient, neon, glass, shadow, 컬러 라인 사용 금지
- Apple 제품 페이지를 복제하기보다 “절제된 정보 설계”만 차용

## 14. 후속 구현의 권장 범위

### 1차: 연결된 제품 경험

전체 메뉴와 반응형 공통 틀을 먼저 만든다. 그중 `기본 정보 입력 → 성향 설문 → 홈 캐러셀 → 활동 상세 → 저장 → 알림 설정 → 내 정보 통계·졸업요건 확인`을 끊김 없이 작동하는 중심 흐름으로 삼는다.

개인 데이터·활동 데이터는 명시적으로 구분한 데모 자료 또는 사용자 수동 입력으로 시작한다. 데모 계정에는 `체험용 데이터`를 표시하고 실제 학생의 데이터처럼 제시하지 않는다. 저장 기능이 브라우저 내부에서만 동작하는 데모라면 이 사실을 표시한다. 실제 학교 비밀번호나 실제 개인 학사자료를 데모 저장소에 넣지 않는다.

### 2차: 학기 의사결정

시간표 조건 입력·후보 비교, 과목 추천 근거, 학기별 계획 이동·재계산, AI 상담의 근거 표시를 연결한다. 필수 제약과 선호 조건의 분리를 검증한다.

### 3차: 운영 연동

공개 정보 수집 정책과 실제 출처를 검증한 뒤 운영 수집기를 연결한다. 개인 연동·푸시 전달·졸업 규정 검증은 각각 성공 기준을 마련해 별도로 확인한다. 미검증 기능을 시연 버튼만으로 구현 완료라고 표현하지 않는다.

자동 수강신청, 실시간 잔여석 감시, 강의 동영상 재생·출석 처리, 전체 LMS 복제, 모든 학과·입학연도의 졸업 규정 완전 자동 판정은 초기 범위에서 제외한다.

## 16. Astra 최종 구현 지시문

이 문서를 **한성대 개인화 학사관리 플랫폼의 최종 제품·UX·디자인 명세**로 사용한다.

### 우선순위

1. 실제 사용자 흐름
2. 데이터 상태와 오류 처리
3. 정보의 정확한 계층
4. 반응형·접근성
5. 시각적 완성도

예쁜 정적 화면보다 **입력 → 저장 → 상태 변경 → 다른 화면 반영**이 먼저다.

### 반드시 구현에 반영할 것

- 왼쪽 사이드바 기반 데스크톱 내비게이션
- 홈 Hero 캐러셀
- 상세페이지 브레드크럼
- 사용자 프로필 카드
- 사용자 통계
- 졸업요건 프로그레스 바
- Notification Center
- 우측 중상단 Toast
- 최초 방문 Cookie Banner
- 수업 성향 Lightbox/Modal
- 학교·LMS·비교과 데이터의 출처 구분
- 데모/사용자 입력/공식 데이터 상태 구분
- 로딩·빈 상태·오류·부분 데이터 상태

### 디자인에서 절대 사용하지 않을 것

- **Side accent bar**
- **Side-tab card**
- 선택 상태를 나타내는 세로 컬러 바
- 카드 옆으로 튀어나오는 `추천/NEW/필수` 탭
- 경고 카드 왼쪽의 두꺼운 컬러 스트립
- 과도한 그림자
- 본문 전체 glassmorphism
- 근거 없는 gradient 장식
- 카드마다 다른 액센트 색을 사용하는 방식

### 대신 사용할 표현

- 명확한 타이포그래피 위계
- whitespace
- 얇은 neutral border
- badge/chip
- icon + label
- section title
- top tabs / segmented controls
- 선택 메뉴 전체의 약한 배경 채움
- 한 영역에 하나의 강한 primary action

### 데이터와 기능에 대한 금지 사항

- 실제 학교 비밀번호 수집 금지
- 확인되지 않은 학교 연동을 `연결됨`으로 표시 금지
- 수강 계획을 이수 완료로 계산 금지
- 시간표 저장을 공식 수강신청으로 표현 금지
- 활동 링크 클릭을 신청 완료로 처리 금지
- 현재 총점만으로 과거 통계를 생성 금지
- 학교 평균·학과 순위·상위 퍼센트를 근거 없이 생성 금지
- 데이터가 없을 때 졸업 퍼센트를 임의 생성 금지
- LMS 수강 목록을 전체 개설 과목 목록으로 취급 금지
- 외부활동 참가를 자동으로 비교과 포인트 인정 처리 금지

### 1차 구현 중심 흐름

`회원가입/로그인`
→ `기본 학적 정보`
→ `홈`
→ `수업 성향 설문`
→ `개인화 Hero/지금 할 일`
→ `활동 상세`
→ `저장/알림 설정`
→ `내 정보 통계`
→ `졸업요건 상세`

그 다음 단계로:

`과목 추천`
→ `시간표 짜기`
→ `학기별 계획`
→ `AI 상담`

을 연결한다.

### 구현 결과 보고 기준

Astra는 결과를 다음 네 가지로 구분해서 보고한다.

1. **UI 구현됨**
2. **로컬 상태/데모 데이터로 동작함**
3. **실제 백엔드와 연결됨**
4. **실제 학교 데이터 연동까지 검증됨**

UI만 존재하는 기능을 실제 연동 완료로 표현하지 않는다.

기존 저장소가 있다면 먼저 구조와 기술 스택을 확인하고 존중한다. 외부 배포, 실제 계정 권한 변경, 학교 계정 로그인 자동화, 프로덕션 데이터 조작은 별도 승인 없이 실행하지 않는다.


## 16.1 최종 UI 체크리스트

Astra 구현 전·후에 아래 항목을 확인한다.

- [ ] 사이드바 선택 상태에 세로 컬러 바가 없는가?
- [ ] 카드 왼쪽/오른쪽에 상태용 컬러 스트립이 없는가?
- [ ] 카드 측면에 돌출된 탭이 없는가?
- [ ] 분류는 badge/chip/top tab으로 처리했는가?
- [ ] 카드가 필요 이상으로 중첩되지 않았는가?
- [ ] 한 화면의 Primary Filled 버튼 수가 과도하지 않은가?
- [ ] 데이터가 없는 영역에 임의 수치가 생성되지 않았는가?
- [ ] Toast와 Notification의 역할이 분리되어 있는가?
- [ ] 브레드크럼이 상세 페이지 계층을 일관되게 보여주는가?
- [ ] 졸업 진행률에 `현재 / 기준`이 함께 보이는가?
- [ ] 계획 중 데이터와 이수 완료 데이터가 구분되어 있는가?
- [ ] 공식 출처/사용자 입력/데모 데이터 상태가 구분되는가?
- [ ] 모바일에서 사이드바가 drawer로 전환되는가?
- [ ] 키보드 포커스와 모달 복귀가 정상인가?
- [ ] 캐러셀 핵심 정보가 이미지 안 텍스트에만 의존하지 않는가?
