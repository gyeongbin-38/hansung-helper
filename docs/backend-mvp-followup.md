## P0 — 실사용·운영 전 완료

### 1. 실계정 COSMOS·종합정보 수집 검증

- [ ] 공통 커밋 SHA, 실행 환경, 학교 계정 확인 범위를 기록한다. 실제 학번·비밀번호·학교 쿠키·전체 HTML은 공개 PR과 로그에 남기지 않는다.
- [ ] 본인 계정으로 로그인 → 수집 중 → 완료/부분 실패 → 새로고침 → 재수집을 실행한다. 화면에 표시되는 출석·제출/응시·이수·포인트와 학교 원문을 대조한다.
- [ ] 느린 응답·인증 만료·구조 오류·정상 빈 목록을 구분한다. 수집 중 다른 학교 세션이 만료돼도 이전 성공 자료와 직접 입력·시간표·관심 목록이 유지된다.
- [ ] 수집 중 앱 로그아웃·탈퇴·계정 전환을 실행해 지연 결과가 재저장되거나 다른 계정에 반영되지 않는지 실제 격리 D1에서 확인한다.

완료 조건: 각 흐름의 기대/실제 결과, 재현 절차, 익명화된 실패 fixture와 회귀 테스트를 후속 PR에 첨부한다. 합성 세션 시험만으로 실제 학교 연동 완료를 선언하지 않는다.

### 2. 수집 시간·요청 예산과 재시도 흐름 확정

- [ ] MVP의 25초 상한을 공통 소스에서 확인하고, 요청 헤더뿐 아니라 리다이렉트와 본문 읽기에도 취소가 적용되는지 검증한다.
- [ ] 실패·시간 초과·취소 시 `lmsPending`/`infoPending`이 무기한 남지 않고, 마지막 확인 시각·보존한 목록/상태 시각·부분 실패가 구분되는지 확인한다.
- [ ] 다수 계정이 동시에 수집할 때 학교별 요청 수·실행 시간·중복 재수집을 측정한다. 같은 학교 페이지/세션의 동시 요청은 제한하고 비밀번호나 학교 쿠키를 공용 캐시에 넣지 않는다.
- [ ] 시간 안에 끝낼 수 없는 수집은 분할/이어받기/작업 큐 등의 대안을 비교해 별도 설계로 제안한다. 재인증·소유자 검증·취소/탈퇴·중복 실행·실패 복구를 포함하며, 인증정보의 장기 보관을 임의로 추가하지 않는다.

완료 조건: 제한 시간 후에도 확보한 부분 자료가 저장되고 재확인 경로가 있으며, 실제 요청 수와 남은 미지원 범위가 기록된다. 학교 서버에 150명 동시 로그인을 보내는 부하 시험은 별도로 범위를 합의한 뒤 수행한다.

### 3. 확장 프로그램의 계정 일치 확인

- [ ] 앱 계정과 COSMOS 로그인 계정을 신뢰할 수 있는 경로로 대조하는 방식을 제안한다. 브라우저가 보내는 학번 문자열만으로 확인 완료로 취급하지 않는다.

완료 조건: 본인 확인 경로와 회귀 테스트를 리뷰한 뒤 로그인 계정의 확장 가져오기 복구 여부를 결정한다. 검증 전 잠정 차단을 유지한다.

### 4. 공개 자료 갱신·운영 준비

- [ ] 소유자와 개발/MVP/운영 D1 및 접근 범위를 확인한다. 운영 계정·세션 자료를 개발 DB로 복제하지 않는다.

## 후속 PR에 남길 결과

각 후속 PR에는 처리한 체크 항목, 공통 기준 SHA와 수정 SHA, 실제 실행한 검증 명령, 성공/실패/미검증 범위, 익명 fixture 또는 재현 절차를 적는다. 구현 변경은 타입·린트·회귀 테스트·빌드 및 해당 API→D1→화면 흐름을 확인한다. 계정·학교 쿠키·비밀번호·개인 원본 파일은 첨부하지 않는다.
