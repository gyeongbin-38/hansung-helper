## 📋 기획팀 — 코딩 없이 할 수 있는 일

### G-1. 실제 COSMOS로 수업 현황 테스트 ⭐ 가장 중요

- **뭘 하는 일**: 내 코스모스 계정으로 수집 스크립트를 실행해서 결과 확인
- **왜**: 지금 수업 현황 기능이 "아마 될 거야" 상태예요. 진짜 계정으로 한번
  돌려봐야 확실해집니다. 지금까지 아무도 실제로 해본 사람이 없어요.
- **하는 법** (5분):
  1. learn.hansung.ac.kr 로그인 → 내 강의실(대시보드)
  2. 키보드 F12 → 맨 위 탭에서 "Console" 클릭
  3. https://wages-stereo-stronger-prepare.trycloudflare.com/lms-collect.js
     열기 → 전체 복사 (Ctrl+A, Ctrl+C) → 콘솔에 붙여넣기 (Ctrl+V) → Enter
  4. `lms-data.json` 파일이 다운로드되면 성공
- **확인할 것**: 내 과목들이 다 나왔나 / 수강한 강의·안 들은 강의 구분이
  맞나 / 과제·퀴즈 마감일이 실제와 같은가
- **결과 적기**: 뭐가 됐고 안 됐는지 메모. json 파일 자체는 개인정보가
  들어 있으니 공유할 땐 과목명만 알려주거나, 파일은 팀장에게만 직접 전달
- **결과**: "됐어요/안 됐어요 + 화면 캡처"만 해도 큰 도움

### G-2. 사이트 전체 사용 테스트

- **뭘 하는 일**: 공유 주소에서 이것저것 눌러보고 이상한 점 기록
- **하는 법**: "체험 모드"로 들어가서 시간표 담기, 과목 추천, 졸업요건,
  학사일정, 알림 등을 써보기 (학교 계정 로그인은 꼭 필요한 경우만)
- **기록할 것**: 어디를 눌렀는데 뭐가 이상했는지 + 캡처. 특히
  - 깨진 화면, 이상한 문구, 작동 안 하는 버튼
  - "이 기능이 있으면 좋겠다" 싶은 것
  - 모바일(폰)로도 한번 열어보기
- **결과**: 발견한 문제 목록 (메모장이나 팀 노션에)

### G-3. 내 학과 졸업 규정 확인 ⭐ 데이터 구멍 메우기

- **뭘 하는 일**: 우리 학과 홈페이지에서 졸업요건을 찾아서 정리
- **왜**: 앱이 학과별 졸업 규정을 자동 수집하는데, 몇몇 학과는 못 찾았어요.
  사람이 직접 찾으면 정확합니다.
- **하는 법**:
  1. hansung.ac.kr에서 내 학과 홈페이지 들어가기
  2. "졸업요건/졸업규정/수료" 메뉴 찾기
  3. 내용이 **글**인지 **표**인지 **첨부파일(hwp/pdf)**인지 **없음**인지 기록
- **특히 확인할 학과**: 디자인대학 학과들(사이트에 내용이 비어 보임),
  자연과학대학(링크 자체가 없어 보임), 역사문화큐레이션·역사콘텐츠
- **결과**: "학과명 / 페이지 주소 / 내용 형태(글·표·첨부·없음) / 학번별로
  다른지 여부" 표로 정리

### G-4. 컴퓨터공학부 → AI·소프트웨어학과 개편 확인

- **뭘 하는 일**: 학교 공지나 학과 페이지에서 "컴퓨터공학부가 이름이
  바뀌었나? 없어졌나?" 공식 근거 찾기
- **왜**: 졸업 규정이 "컴퓨터공학부"로 나오는데 현재 강의 목록에는
  "AI·소프트웨어학과"가 있어요. 둘이 같은 학과인지 공식 확인 필요
  (추측으로 연결하면 잘못된 졸업 기준을 보여주게 됨)
- **결과**: 공식 페이지 주소 + 한 줄 요약 ("OO년부터 OO로 개편")

### G-5. 사용자 의견 수집

- **뭘 하는 일**: 주변 학생 3~5명에게 사이트 보여주고 반응 메모
- **물어볼 것**: "뭘 하는 앱인지 바로 이해됐어?" / "제일 쓸 것 같은
  기능은?" / "뭐가 제일 불편해?" / "시간표 짤 때 에브리타임 대신
  쓸 마음 생겨?"
- **결과**: 인터뷰 요약 (사람당 3~5줄)

### G-6. 문구·정책 리뷰

- **뭘 하는 일**: 앱 안의 설명 문구들이 학생 입장에서 자연스러운지 검토
- **예시**: "공식 사정 대체 아님" 같은 고지 문구, 온보딩 설문 질문 6개,
  알림이 "마감 7일 전"인데 3일이 낫지 않나? 같은 기준 판단
- **결과**: 고치면 좋겠는 문구 목록 + 이유

## 🔧 백엔드팀 — 서버/데이터 쪽 일

상세 기술 문서는 `docs/backend-tasks.md`에 있음 (파일 경로·수용 기준 포함).
여기는 쉬운 설명 + 우선순위만.

### B-1. 로그인할 때 서버가 수업 정보 자동 수집 ⭐ 최우선

- **쉬운 설명**: 지금은 사용자가 수동으로 스크립트를 실행해야 하는데,
  로그인할 때 서버가 코스모스에 접속해서 "뭘 들었고 안 들었는지"를
  자동으로 긁어오게 만들기. 로그인 한 번이면 끝.
- **기술 메모**: 로그인 때 이미 코스모스 세션이 열림 (`lib/server/school.ts`).
  그 세션으로 과목별 페이지 4개씩 더 가져오면 됨. 서버에는 DOM 파서가
  없어서 HTMLRewriter 써야 함.
- **주의**: 과목 많으면 수십 개 페이지 요청 → 학교 서버에 부담. 병렬은
  4개 정도로 제한, 20초 넘으면 부분 결과만 저장.

### B-2. 수업 정보 최신화 방법 정하기

- **쉬운 설명**: 로그인할 때만 수집하면 며칠 지나면 옛날 정보가 됨.
  "최신으로 만들려면 다시 로그인" 할지, 다른 방법을 만들지 결정.
- **중요**: 비밀번호는 절대 저장하면 안 됨 (보안 규칙). 그래서 방법을
  먼저 정하고 구현 — 문서에 선택지 정리해둠.

### B-3. 공지·일정 데이터 자동 갱신

- **쉬운 설명**: 지금 학사일정·활동 목록은 프로그램 파일 속에 박혀 있어서
  바꾸려면 다시 올려야 함. 데이터베이스에 저장하게 바꾸면 사이트 그대로
  두고 내용만 갱신 가능.
- **기술 메모**: D1 테이블 하나 만들고, 읽는 쪽은 DB 우선+파일 폴백.

### B-4. 코드 정리 (프로필 검증)

- **쉬운 설명**: 사용자 정보를 저장할 때 검사하는 코드가 한 파일에 몰려
  있어서, 필드 추가할 때마다 복잡해짐. 정리해서 한 곳만 고치면 되게.

### B-5. 보안 점검

- **쉬운 설명**: 로그인 세션 정리, 보안 헤더 같은 안전장치 보강.
  실제 서비스에 올리기 전에 꼭 필요한 작업.

### B-6. 진짜 서버에 올리기 (배포)

- **쉬운 설명**: 지금은 내 PC에서만 돌아가서 터널로 보여주는 상태.
  Cloudflare에 계정 권한을 받으면 진짜 주소로 올릴 수 있음.
  **필요한 것**: Cloudflare 계정 + 프로젝트 권한 (팀장에게 요청)
