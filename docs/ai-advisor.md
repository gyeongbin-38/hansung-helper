# AI 학사 도우미

`#advisor`는 서비스 전반의 사용 방법을 안내합니다. 기능별 가이드에서 시간표·수업과제·졸업요건·계정·설문 등의 사용법을 묻고 해당 화면으로 이동할 수 있습니다. 활동 추천·공고 요약은 비교과·대외활동의 “AI에게 추천받기”에서 별도로 제공합니다. 기존 규칙 안내도 별도로 사용할 수 있습니다.

- 모델: Cloudflare Workers AI `@cf/google/gemma-4-26b-a4b-it`. 추가 패키지·브라우저 API 키 없이 `AI` 바인딩을 사용합니다.
- 서버: `POST /api/advisor`. 같은 출처 JSON, 유효한 계정 세션, 최대 600자 질문과 최근 2회 대화를 받습니다. 이전 대화는 클라이언트가 전달한 비신뢰 JSON 참고 자료로만 넣으며 `assistant` 역할 메시지로 전달하지 않습니다. 실제 사용자 역할에는 마지막 질문만 추가합니다. 시스템 역할 주입과 다른 계정의 컨텍스트 전달은 허용하지 않습니다.
- 기본값은 개인 학사 정보 미사용입니다. 사용자가 선택한 경우에만 서버가 현재 계정의 저장 자료에서 허용된 학사 요약을 구성합니다. 클라이언트가 보낸 프로필은 사용하지 않습니다.
- 자동 전송 범위: 학과·입학연도·계획 과목과 합산값·직접 입력값의 합계·학교 학점/포인트 요약·일주일 마감. 이름·학번·성적·개인 일정 제목·학교 쿠키·비밀번호·원문 HTML은 제외합니다. 질문에 직접 쓴 내용과 최근 답변은 모델로 전달되므로 UI에 안내합니다.
- 공개 데이터는 기존 D1 스냅샷 우선/번들 폴백으로 읽습니다. 출처 화면과 기준일은 서버에서 만들고, 모델이 임의로 생성한 링크를 실행하지 않습니다.
- 질문·이전 대화에 명시적인 비밀번호 대입, 학번, 세션 쿠키, 알려진 토큰 형식이 있으면 모델 호출 전에 거부합니다. 탐지값을 응답·로그에 되풀이하지 않습니다. 이는 알려진 형식의 실수 방지이며, 모든 비밀값이나 인코딩·우회 표현을 인식하는 보장은 아닙니다.
- 모델 답변의 HTTP(S) 주소·`www.` 주소·`javascript:`·HTML data 주소는 서버에서 거부하고 기존 답변 실패 흐름으로 처리합니다. 검사 전 호환 문자와 숨은 제어 문자를 정규화합니다. 화면은 기존처럼 React 일반 텍스트로 표시하며 출처 이동은 서버가 구성한 항목만 사용합니다.
- 상담은 읽기 전용이며 졸업 판정·수강신청·삭제를 실행하지 않습니다. 수강 계획, 사용자 입력, 학교 수집본을 구분합니다.
- 계정당 15분에 10회, 서비스 전체 UTC 하루에 100회로 제한합니다. 기존 `academic_login_limits`에는 별도 접두사의 카운터만 기록합니다. 질문과 답변은 앱 서버·DB에 보관하지 않습니다. 실제 과금은 Cloudflare 요금제와 모델 사용량을 따릅니다.
- 일일 한도 소진 시 `POST`는 `DAILY_QUOTA` 코드의 429를 반환하고 `GET`은 `dailyExhausted: true`를 알립니다. 화면은 이 신호로 AI 입력을 잠그고 기본 안내 전환을 안내합니다. `GET`의 한도 조회는 카운트를 올리지 않는 읽기이며, 조회 실패는 소진으로 간주하지 않습니다.
- 답변을 반환하기 전에 세션을 다시 확인합니다. 로그아웃·화면 이탈·개인 정보 선택 변경 시 이전 대화와 진행 요청을 정리합니다. 모델 실패/제한 시 질문을 유지하고 재시도·기본 안내 전환을 제공합니다.

`GET /api/advisor`는 바인딩 유무만 알립니다. 모델 추론 성공까지 보장하는 건강 점검은 아닙니다. `HANSUNG_ENABLE_AI=0`으로 배포하면 AI를 끄고 기본 안내를 유지합니다. 로컬은 기본 비활성이며 `HANSUNG_ENABLE_AI=1`로 빌드하면 원격 AI 바인딩을 연결합니다. 로컬에서도 실제 호출은 사용량에 포함됩니다.

## 활동 추천 워크스페이스

`#activities/recommend`와 `#activities/recommend/{활동 ID}`는 다음 실제 상태만 표시합니다. 기존 `#advisor/{활동 ID}`·`#advisor/activities`·`#activities/apply*` 진입은 새 경로로 연결합니다. 나의 비교과 브리핑은 기본으로 접혀 있으며 클릭·키보드로 펼칩니다.

- 학교 계정 연결: 현재 앱 계정 세션. 학번·비밀번호는 상담 화면이나 AI 메시지에 포함하지 않습니다.
- 추천 조건: 누적 비교과 포인트와 키우고 싶은 역량(`COMPETENCY_GOALS`)을 고릅니다. 선택한 역량은 계정 프로필 `actGoals`에 저장되어 다른 화면에서도 유지됩니다.
- 추천 알고리즘: 포인트 부족 여부와 목표 역량으로 네 케이스(포인트+역량 병행·포인트 우선·역량 집중·기본 추천)를 나누고, 접수 상태·포인트·인증·취향 설문을 점수화해 추천 이유를 함께 표시합니다. 공개 목록에는 역량 태그가 없어 제목·운영 부서의 키워드로 근사하며, 실제 역량 인정 여부는 학교 기준을 따릅니다.
- 활동 탐색: 추천 목록과 별도로 '직접 찾기'에서 D1/번들 공개 스냅샷과 사용자가 직접 등록한 활동을 로컬에서 검색·필터합니다. 사용자 요청 시 학교 사이트를 실시간 탐색하지 않습니다.
- 직접 등록 활동은 사용자 입력 정보로 구분하며 학교 수집일·공식 공고로 표시하지 않습니다. AI 요청 시 현재 계정에 저장된 선택 활동만 서버에서 조회하며, 다른 활동이나 개인정보 전체를 전송하지 않습니다.
- AI 요약: 활동을 고르면 공고 요약(기간·포인트·수집일·확인 필요 항목)을 보여주고, AI에게 활동 요약이나 추천 이유를 물어볼 수 있습니다. 신청서 초안 작성·편집 기능은 제공하지 않습니다.
- 최종 접수: 관심이 가면 공식 공고/신청 화면에서 본인이 확인하고 접수합니다. 현재 공개 목록은 지원 자격·필수 서류·접수 완료 여부를 제공하지 않으며, 앱은 자동 제출이나 선발 가능성을 표시하지 않습니다.

공식 스마트자기관리시스템의 인증·접수 폼 연동은 검증된 서버 커넥터가 없으므로 범위에 포함하지 않습니다. 향후 연동하더라도 최종 제출 전 사용자 확인을 별도로 받아야 합니다.

## 질문 범위와 차단

프롬프트 조작·역할 변경·숨겨진 시스템 지시와 내부 설정/비밀값 요청·보안 관련 질문은 처리하지 않습니다. 보안 주제를 포함한 활동에 대한 질문도 이 범위 제한을 적용합니다. 동일한 입력 정책을 브라우저 기본 안내와 서버 API에 적용하고, 서버는 클라이언트가 보내는 사용자·답변 대화 이력을 추론·할당량 차감 전에 검사합니다. 서비스 화면의 알림 설정이나 로그인·학교 연결 사용법은 정상 안내합니다. API의 `purpose`는 `service` 또는 `activity`이며 선택 활동과 목적을 서버에서도 확인합니다.

모델 시스템 지시에는 서비스/활동별 범위와 근거 자료를 지시로 따르지 않는 원칙을 둡니다. 이 정책은 명확한 범위 밖 요청을 선제 차단하는 방어이며, 문자열 검사와 시스템 지시만으로 임의의 프롬프트 인젝션을 완전히 차단한다는 보장은 아닙니다. [OWASP의 프롬프트 인젝션 방어 안내](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)처럼 입력 검사·지시와 데이터 구분·최소 권한을 함께 적용합니다. 인증 정보는 모델 컨텍스트에 포함하지 않고 기존 세션·출처·호출 제한을 유지합니다.

잔여 위험: 활동 공고·일정·과목명·사용자가 직접 등록한 문구를 통한 간접 주입, 인코딩·다국어 질문, 오염된 과거 답변으로 상담 내용이 왜곡될 수 있습니다. 모델에는 학교 연결·DB 조회·저장·삭제·신청 도구를 제공하지 않으므로 답변만으로 해당 작업을 실행할 수 없습니다. 개인 학사 요약을 선택하면 허용된 본인 정보가 모델에 제공되는 만큼, 주입이 답변에서 그 정보를 반복하게 만들 가능성까지 없애지는 못합니다. 프롬프트에는 비밀값을 두지 않으며 시스템 지시문 자체의 비공개성에 보안을 의존하지 않습니다. 현재 회귀 테스트는 모의 모델로 서버의 역할·데이터·출력 경계를 확인하고, 실제 모델에 대한 공격 성공률을 측정한 테스트는 아닙니다.
