# AI 활동 작업 공간

2026-11-13 사용자 요청에 따라 기존 학사 상담을 활동 찾기 → 신청 준비 → 내용 확인 흐름으로 확장한다. 기존 Cloudflare Workers AI·계정 인증·D1 구조를 사용하며 새 에이전트 프레임워크나 의존성을 추가하지 않는다. 기존 프로젝트를 확장하는 경우 해당 스택을 유지한다는 `build-agents` 지침을 적용했다.

## 사용자 흐름

1. `#advisor`에서 비교과를 검색하거나 직접 등록한 대외활동을 선택한다.
2. 학교 연결 카드에서 저장된 학사 세션의 상태와 만료 기한을 확인한다. 필요하면 세션으로 재수집하거나 별도 인증 폼으로 학교에 다시 연결한다. 체험 이용자는 기존 학교 로그인 화면으로 이동하고 성공 후 작업 화면으로 돌아온다.
3. 선택한 공고의 기간·포인트·출처·수집 기준일을 확인하고 기본 안내 또는 AI 상담으로 참여 목적과 준비 내용을 정리한다. 개인 학사 요약 사용은 기본 해제다.
4. 신청 메모를 편집하고 필요한 항목을 직접 확인한 후 공식 공고·신청 화면을 연다. 메모 복사와 링크 열기는 접수 완료를 의미하지 않으며 활동의 접수 기록을 바꾸지 않는다.

대화와 신청 메모는 현재 화면에만 둔다. 활동·계정 변경과 화면 이탈 시 이전 요청을 취소하고 응답을 폐기한다. 학교 비밀번호는 대화와 분리된 폼에서 받고 제출·닫기·화면 이탈 시 비운다. 비밀번호·학교 쿠키는 모델 입력에 포함하지 않는다. 모델 답변은 텍스트로 렌더링하고 실행 가능한 링크와 코드는 만들지 않는다.

## 실제 연동 범위

- 학사 계정: 기존 `/api/account/login`, 재인증은 `/api/account/lms-refresh`.
- 저장된 학사 세션: `GET /api/account/lms-refresh-session`이 `{configured, available, expiresAt}`만 반환한다. `available`은 저장된 세션의 보관 상태이며 학교 서버의 즉시 유효성을 보장하지 않는다. `POST`는 종합정보·COSMOS를 확인하고 재수집한다.
- 학교 세션 만료(`X-Hansung-School-Session: expired`)와 앱 로그인 만료(`X-Hansung-Session-Invalid: 1`)를 구분한다. 학교 세션 만료만으로 앱 계정을 로그아웃하지 않는다.
- 학사 세션은 최초 인증에서 고정된 2시간 기한을 사용한다. 재사용은 기한을 늘리지 않는다. 비밀번호로 학교 인증에 성공하면 새 기한을 설정할 수 있다. 자세한 저장 규칙은 [session-vault.md](session-vault.md)를 따른다.
- AI 상담은 기존 `/api/advisor`의 실제 세션 확인·계정별 호출 제한·일별 호출 제한·허용된 학사 요약만 사용한다. AI를 사용할 수 없으면 기본 안내를 제공하며 AI 응답으로 표시하지 않는다.

## 조사 근거와 후속 연동

참고 제품은 [Pickle 공식 사이트](https://www.pickle.com/)와 [로그인 카드 안내](https://www.pickle.com/help/connect/save-login)다. 참고한 것은 별도 인증 입력, 실제 작업 진행 상태, 실행 전 사용자 확인 흐름이다. Pickle의 비밀번호 저장 방식 자체를 복제하지 않으며 이 서비스는 학교 비밀번호를 저장하지 않는다.

[한성대 비교과 공개 목록](https://hsportal.hansung.ac.kr/ko/program/all)과 공식 사이트가 제공하는 [로그인 스크립트](https://hsportal.hansung.ac.kr/modules/coursemos/scripts/script.js), [신청 스크립트](https://hsportal.hansung.ac.kr/modules/eco/scripts/script.js)를 읽어 확인했다. 비교과 사이트는 `Coursemos.login()` 인증을 사용하고, 신청 시 개인별 사전 확인과 신청 페이지 진입을 거친다. 외부 신청 주소를 사용하는 공고와 팀 신청도 있으므로 목록만으로 동일한 접수 폼을 가정할 수 없다.

현재 암호화 볼트는 `info.hansung.ac.kr`와 `learn.hansung.ac.kr`의 쿠키만 허용한다. 따라서 비교과 포털에 로그인되어 있다고 표시하거나 이 쿠키를 포털로 전송하지 않는다. 실제 자동 접수의 후속 연동에는 비교과 포털 인증, 개인별 지원 자격·필수 동의·신청 문항 조회, 사용자가 확인한 내용을 제출할 방법, 중복 접수 방지와 접수 결과 재확인이 필요하다. 이번 변경은 공식 신청 화면으로의 명시적 인계까지 지원한다.

## 정적 이미지

후속 요청에 따라 마스코트 애니메이션·리그·이벤트·설정은 제거했다. 기존 로고와 정적 일러스트만 유지한다.

## 검증

타입 검사·린트·전체 회귀 검사·프로덕션 빌드를 실행하고, 브라우저에서 활동 선택·메모·확인 단계·인증 입력 분리·모바일 배치를 점검한다. 학교 비밀번호와 실제 접수는 사용하지 않으며 브라우저 인증 시나리오는 명시적인 테스트 응답으로 확인한다. 실제 학교 인증 성공·자동 접수 검증으로 해석하지 않는다.
